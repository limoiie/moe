# 底部动作条取代常显提示条，键位块统一用 Kbd 呈现

面板底部原本常显一整行键位提示（`↓ 导航 / ⏎ 应用 / ⌥⏎ 复制 / ⌘K 动作 / ⌘P 浏览 / ⌘N 新建 / ⌘M 侧栏 / ⌘⇧A 附件 / Esc 回退`）。它有两个问题：

- **信息密度与价值倒挂**：绝大多数键位在绝大多数时刻都用不上，却一直占着一整行；真正「现在能做什么」反而要靠用户自己从一排键位里认出来。
- **与 Raycast 手感不一致**：Raycast 把可做的事收进右下的两个按钮（主操作 + Actions），按压后展开完整动作清单。

同时，Input Bar 与 Result List 是同一个视觉网格（图标一列、标题一列），但两者的图标尺寸（18 vs 16）、左内边距（16 vs 20）与字号（`text-lg` vs `text-sm`）各不相同，扫描时能看出错位。

## 决定

- **Action Bar（底部动作条）**：面板右下角悬浮两个按钮——**主操作**（Focused Item 的主操作标题 + 其键位；生成中变为「停止生成」+ Esc）与**动作**（`⌘K` / `⌘⇧P`）。带阴影与 `backdrop-blur`，浮在列表之上；列表与详情补 `pb-14` 让最后一屏内容不被遮住。
- 常显的 Hints Bar 删除。可做的事集中到两处：动作条（主操作 + ⌘K）与 ⌘K 打开的动作层（含 Extension 真的声明了的 Browse ⌘P / New ⌘N 入口）。
- **动作层成为独立一层**：Esc 从动作层先回结果层（与 ⌘K 按钮互为开关），不再直接跳回命令盘。
- **Input Bar 与列表同网格**：搜索图标 16px、`text-zinc-400`，行内边距 `px-5`（= list `px-2` + row `px-3`），间距 `gap-2.5`，字号 `text-sm`——与列表行逐项对齐。
- **Kbd 组件（`ui/src/kbd.ts` + `.moe-kbd`）**：所有键位展示都走它——每个键一个方块，字符水平居中、块高一致、行内基线对齐（shadcn Kbd 同款）；一个语义有多个键位时用 ` / ` 分隔（如 `⌘K / ⌘⇧P`），按钮等窄处只画第一个键位。展示串仍来自 `moe-core::keymap`，视图层不发明键位。

## 代价

- 系统键位（⌘M 侧栏、⌘⇧A 附件、⌘P/⌘N、⌃[/⌃]）不再常显，可发现性由 README、tooltip 与动作层承担。
- 动作条浮在内容之上，长内容需要额外底部留白（已加），且它是「覆盖」而非「挤占」布局，改布局时要跟着调。
- 主操作按钮的标题来自 Extension 的动作标题，过长会撑宽按钮（当前动作标题都在三四个字内）。
