# DeepSeek context caching and DeepSeek Harness's append-only session design

Research note, 2026-10-10. Every claim below cites a primary source (api-docs.deepseek.com, the
deepseek-harness repo and docs) fetched live on 2026-10-10; exact quotes are verbatim; URLs are in
[Sources](#sources). Inference is labeled as inference; unverified items are in
[Verification notes](#verification-notes).

## Context

MOE-0017 adds a multi-round tool loop to AI conversations, forcing a history question: **collapse**
each agentic turn (persist only question + final answer, replay a clean transcript) or **persist
faithfully** (store and replay every round, append-only). The owner's objection to collapse was a
KV-cache intuition — DeepSeek's automatic context caching prices prefix hits at 1/50 of misses, and
DeepSeek Harness ("dsh") is reportedly designed for very high cache-hit ratios. This note verifies
the mechanics and settles the question (decision: ADR-0039 — persist faithfully).

## Findings

### DeepSeek context caching (api-docs.deepseek.com/guides/kv_cache)

> Note: `/guides/context_caching` 404-redirects; the real page is `/guides/kv_cache`.

- **Automatic, no code changes:** "The DeepSeek API Context Caching on Disk Technology is enabled
  by default for all users, allowing them to benefit without needing to modify their code."
  "If subsequent requests have overlapping prefixes with previous requests, the overlapping part
  will only be fetched from the cache, which counts as a 'cache hit.'"
- **Prefix-unit matching** (changed with Sliding Window Attention): "Each cached prefix is an
  independent, complete unit. A subsequent request can only hit the cache if it **fully matches**
  a **cache prefix unit**." Units are persisted at "the end position of the user input" and "the
  end position of the model output" of each request, on common-prefix detection across requests,
  and "at fixed token intervals" for long inputs/outputs.
- **Example 1 (the persist case):** "A user's first-round request is `A + B`, and the second-round
  request is `A + B + C`. The second request can fully match the cache prefix unit `A + B`,
  hitting the cache for `A + B`."
- **Example 2 (the collapse case):** "…first-round request is `A + B`, and the second-round request
  is `A + C`. The second request cannot hit the cache… However, at this point the system will
  detect that the two requests share a common prefix `A`, and persist `A` as a cache prefix unit."
- The 2024 launch announcement is blunter: "only requests with identical prefixes (starting from
  the 0th token) will be considered duplicates. **Partial matches in the middle of the input will
  not trigger a cache hit.**" Savings: "up to 90%… Even without any optimization, historical data
  shows that users save over 50% on average"; "Multi-turn conversation: The next turn can hit the
  context cache generated by the previous turn" is listed as a classic scenario
  (https://api-docs.deepseek.com/news/news0802).
- **Best-effort + TTL:** "The cache system works on a 'best-effort' basis and does not guarantee a
  100% cache hit rate." "Once the cache is no longer in use, it will be automatically cleared,
  usually within a few hours to a few days."
- **Pricing** (https://api-docs.deepseek.com/quick_start/pricing, per 1M tokens, off-peak/peak):

| Input tokens | deepseek-flash (V4.1-Flash) | deepseek-v4-pro |
| --- | --- | --- |
| Cache **hit** | $0.003 / $0.006 | $0.022 / $0.044 |
| Cache **miss** | $0.15 / $0.30 | $0.66 / $1.32 |
| Output | $0.60 / $1.20 | $1.98 / $3.96 |

  Hit is **50× cheaper** than miss on flash (30× on pro). Peak hours: 01:00–04:00 and 06:00–10:00
  UTC, weekdays, excluding Chinese public holidays.
- **Observability:** `usage.prompt_cache_hit_tokens` / `usage.prompt_cache_miss_tokens`.
- **Stateless API:** "The DeepSeek `/chat/completions` API is a 'stateless' API… the user must
  concatenate all previous conversation history and pass it to the chat API with each request"
  (https://api-docs.deepseek.com/guides/multi_round_chat).
- **Tool-call messages in the cache**: the guide never mentions `tools`/tool-role messages — no
  exclusion is stated either; matching is defined generically over the request prefix. Best
  available corroboration: dsh's real-API e2e test asserts that an appended request "reads more
  cached tokens" in a conversation *with tool calls* (dsh repo,
  `.agents/notes/implemented/feature/2026-09-02-in-history-system-prompt-replacement.md`). Mark
  "caching behaves identically for tool messages" as **not explicitly documented**.

### The `reasoning_content` echo rule is cross-turn (api-docs.deepseek.com/guides/thinking_mode)

- "If the request **carries the `tools` parameter**: the `reasoning_content` of **all previous
  turns** should be passed back to the API and will be concatenated into the context."
- "…the `reasoning_content` must be fully passed back to the API in **all subsequent requests —
  even for turns where the model did not perform a tool call**. If your code does not correctly
  pass back `reasoning_content`, the API will return a **400 error**."
- "Additionally, **in the Turn 2 request, we still pass the `reasoning_content` generated in
  Turn 1** to the API." The sample code appends assistant messages whole:
  `messages.append({'role': 'assistant', 'content': …, 'reasoning_content': …, 'tool_calls': …})`.
- Without `tools`, reasoning passed back "will be ignored and will not be concatenated into the
  context."
- Related hard constraint: "The Chat Completion API **does not support inserting tool calls
  mid-conversation**" (only the Anthropic/Responses formats do)
  (https://api-docs.deepseek.com/guides/tool_calls) — a collapsed turn cannot be faithfully
  reconstructed later on the wire Moe speaks.

### What DeepSeek Harness (dsh) actually does (github.com/deepseek-ai/deepseek-harness)

- **Append-only durable log is the single source of model context.** `core/session` owns "the
  append-only `SessionEvent` log"; "The session log is the source of the context the model sees.
  `deriveMessages()` projects model history from it." Standing rule: "**Model-visible means
  logged.** Every model request must be reconstructable from the log." (docs/architecture.md)
- **Tool rounds and reasoning are durable and replayed.** `turn/*`, `step/*`, `user/message`,
  `assistant/message`, `tool/*` are durable session events; the wire history is a fold of surface
  events in seq order; each `assistant/message` "embeds the exact compact timed stream that
  produced its assembled content" (reasoning included). **dsh is design option (B): faithful
  persist + replay.**
- **Cache-first prompt assembly is an explicit design goal.** Decision note: "Every system prompt
  change costs the whole provider prefix cache… the request's message 0 changes and the DeepSeek
  context cache misses from the first token. Long agentic sessions pay this repeatedly." Fix: on
  models declaring `systemPromptUpdate: 'in-history'` (declared for `deepseek-flash`), the harness
  appends the new prompt **after the cached history** — "the prefix stays warm." `PromptContext`
  is "the **cache-safe** counterpart to `PromptSection`" (docs/subsystems/system-prompt.md).
- **Release notes:** v0.1.5-alpha.1 (2026-09-08) "Support dynamic system prompt updates **without
  invalidating KV Cache** when the configured model explicitly declares support"; v0.1.7-rc.2
  (2026-09-24) same for dynamic tool additions; v0.1.1-rc.1 (2026-08-21) UI precision fix for
  "**99.x% cache-hit ratios**" — the ratio is a first-class displayed metric.
- **Compaction is the pressure valve, and it knowingly costs the cache.** Capability seam
  (`ctx.compaction`), triggers `'pressure' | 'context-overflow'`; a successful run replaces a span
  of surface nodes with one summary `user/message` (shadowed events stay in the log but leave the
  model-visible surface); "Region boundaries preserve tool-call/result pairing but not whole
  turns"; system-prompt node 0 "is never inside a compaction range"; an optional
  `ctx.toolResultPruner` deterministically truncates over-budget tool results (head/tail
  retention). The in-history note's framework: a surface replacement moves `replaceGeneration`,
  which "starts a new request series," and "A series start already costs the cache" — so dsh
  re-baselines there for free and otherwise never mutates the warm prefix
  (docs/subsystems/compaction.md).
- **No official quantified "high KV cache hit rate" claim** was found in README/docs/release
  notes; the strongest signals are the two "without invalidating KV Cache" features, the cache-hit
  e2e assertion, and the 99.x% display-precision note. The owner's recollection is directionally
  corroborated, not a quote.

### Collapse (A) vs persist (B) — analysis *(inference built on the verified mechanics above)*

Setup: turn N ran rounds `U_N → A_N1(tool_calls) → R_N1 → … → A_Nk(final)`; cache prefix units
exist at each request boundary.

- **(B) persist:** turn N+1 sends `[…U_N, A_N1, R_N1, …, A_Nk, U_{N+1}]` — an exact continuation,
  i.e. the guide's Example 1 verbatim. The entire history bills at hit price ($0.003/M off-peak
  flash). Costly tool results are never re-run: they sit in history, visible to the model.
- **(A) collapse:** turn N+1 sends `[…U_N, A_N-final-only, U_{N+1}]`. The sequence diverges from
  the last cached prefix right after `U_N` — Example 2 semantics: hits only through the last
  persisted common unit, the rewritten tail re-billed at miss pricing *every turn*; and per
  news0802 "partial matches in the middle… will not trigger a cache hit." Additionally, since
  later requests still carry `tools`, a collapse that strips `reasoning_content` from retained
  assistant messages is the documented 400 trap.
- **(B)'s growth cost is hit-priced:** replaying 1M cached tokens costs $0.003/M off-peak on
  flash; with a 1M-token context, faithful replay is cheap until context pressure forces
  compaction — exactly dsh's posture (persist faithfully; compact only under pressure; accept the
  cache loss at that re-baseline).
- **Caveat:** caching is best-effort with a TTL of "a few hours to a few days" — (B)'s advantage
  holds within a warm-cache window, not indefinitely.

## Fit for Moe (decision recorded in ADR-0039 / MOE-0017)

- **Persist faithfully, dsh-style:** the conversation record is append-only — questions, answers,
  reasoning, tool calls, tool results — and every request for an Agentic Conversation replays it
  whole, with `tools` attached and `reasoning_content` echoed on every assistant message.
- **Never mutate a warm prefix:** no history rewriting, no post-hoc system-prompt edits; the
  system prompt is a stable head.
- **Agentic Conversations always send `tools`** on later requests, even if the global kill-switch
  flips afterwards (their history contains tool rounds; chat-completions can't pair tool messages
  without `tools`, and reasoning-less replay would 400).
- **Pre-feature conversations stay plain forever** (no stored reasoning → sending `tools` alongside
  them is the documented 400 trap; the capability flag rides on the conversation).
- **Compaction deferred** out of v1 (1M context; ⌘N New Chat is the escape hatch); revisit
  dsh-style summarize-and-replace under pressure if conversations ever hit walls.
- This **amends ADR-0024's stance** ("聊天历史只存回答") for Agentic Conversations: reasoning is
  now persisted as replay material and re-rendered on reopen — it is still never the answer, never
  copied, never written back.

## Verification notes

- **"cache-first loop" on the Reasonix integration page**: not present on the current EN or ZH
  pages (fetched both) — either removed or misremembered; unverified.
- **Explicit official "high KV cache hit rate" claim for dsh**: not found; only the indirect
  evidence quoted above.
- **Caching semantics for `role: "tool"` messages**: not addressed in the kv_cache guide (no
  exclusion stated either); dsh's e2e assertion with tool calls is the best corroboration.
- **Minimum cacheable length**: the "64 tokens as a storage unit" figure is from the 2024-08-02
  announcement; the current guide gives no number ("fixed token intervals" only). Treat as
  possibly stale.
- **Whether *omitting* (vs truncating) a prior assistant message triggers the 400**: the doc
  specifies only the missing-`reasoning_content` case.
- **Fetch quirks**: `/guides/context_caching` silently falls back to the first-API-call page; the
  api-docs sitemap lists no "DeepSeek Harness Guide" page (the quick-start link points off-site,
  presumably the dsh docs site, not crawled beyond the repo).
- The collapse-vs-persist comparison is **inference** from the documented matching semantics
  (Examples 1–2, news0802), not a measured benchmark; the cost figures use verified 2026-10-10
  pricing.
