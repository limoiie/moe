# 与宿主应用的文字互动统一走 TextTarget 边界，剪贴板粘贴为全平台降级

"读选区/写回文本"是整个产品的技术风险最高点，且各平台能力悬殊：macOS 有 Accessibility API（需用户授权），X11 有成熟方案，Wayland 沙箱下读不到任何应用的选区，Windows 走 UIA。决定抽象 TextTarget 边界（读选区、替换、插光标），macOS 主路径用 AX API，所有平台保留统一的降级路径：暂存剪贴板 → 写入结果 → 模拟粘贴 → 恢复剪贴板。Linux 首版只承诺 X11 + Wayland 降级；Windows 后置。Command 层不感知具体平台手段。

## 增补：剪贴板也是平台能力（IIE4AD-364）

"复制"类动作（SecondaryCopy 的默认语义）与 WriteBack 是两件事：前者只写系统剪贴板、**不动宿主应用**，后者才走 TextTarget 回写。因此平台层提供独立的 `clipboard::copy`（macOS 复用回写降级的同一 NSPasteboard 实现）；扩展返回 `ActionResult::Silent`，由面板自己给一次轻量 toast 作为反馈。这样剪贴板能力不污染 Command 契约，也不需要新枚举变体。

## 增补：选区也是 AI 提问的上下文（IIE4AD-37x）

呼出面板前抓到的 Selection 不只用于回写，也作为提问上下文：AI 扩展把选区拼进发给模型的提示
（问题在前、选区以代码块附后；问题里已含这段文字则不重复；超长截断并注明），历史里仍只存问题本身。
平台只负责把选区递给扩展（`invoke`/`fallback_command` 的 `selection` 参数），拼不拼由扩展决定。

## 增补：选区读取的剪贴板拷贝兜底

有些应用（如 Zed）不对外暴露 `AXSelectedText`，AX 读回来永远是空。读取路径在 AX 之后加
**剪贴板拷贝兜底**：快照 → 合成 `⌘C` → 读剪贴板 → 恢复快照。因为时机在呼出面板前、
宿主应用仍有焦点，`⌘C` 拷的就是它的选区。用「⌘C 前后剪贴板是否变化」区分
「应用没有选区」与「拷到了选区」——剪贴板没变就不把旧内容当选区（代价：
选区恰好等于旧剪贴板内容的罕见情况会漏读）。

## 增补：兜底判定的收紧与观测的拆离（MOE-0013）

兜底路径落地后又收紧两处。其一，**空选区范围不触发兜底**：`AXSelectedTextRange` 存在且
`length <= 0` 时就是光标，`⌘C` 与等待预算都不再跑；范围缺失（应用根本不暴露）才保留兜底
——那正是兜底存在的场景。其二，**兜底的观测移出呼出路径**：`TextTarget::capture_selection`
呼出前只发 `⌘C`，再给约 20ms 短宽限（足够事件派发到仍持焦点的宿主应用，也覆盖正常应用的
落盘时间 5–15ms）；宽限内落盘的复制照旧在显示前完成读取与恢复，行为与从前一致；宽限内没有
落盘的（常态是「没有选区」）立即显示面板，剩余观测（总预算约 100ms）、读回与恢复交给后台线程
（`Capture::Pending`），选区可能比面板晚几十毫秒进入 `state.selection`——命令在调用时才读它，
用户来得及。

两条剪贴板纪律随之确立：快照只在拷贝确实落盘后恢复（从未落盘 = 剪贴板未被触碰，不做恢复，
也不再每次呼出都改写剪贴板）；落盘后若剪贴板又被写过（例如用户在面板里触发「复制」），跳过
恢复，不让快照覆盖新内容。代价：面板显示后的约 100ms 内若立即调用命令，晚到的选区可能尚未
进入上下文。

## 增补：兜底判定的三处修正——落盘即选择、窗口放到面板之后、AX 判定三分（MOE-0066）

实际使用里出现了一种「粘住」的失败：在自绘编辑器（如 Zed 的对话输入框这类 textarea 形态的
控件）里选中文字后呼出面板，命令偶尔报「没有选区」；更糟的是，**一旦失败，之后每次重选同一段
文字都继续失败**，重启 Moe 也不恢复。三处修正如下。

其一，**落盘即选择**。旧判定用复制前后的文本比较来区分「应用真的复制了选区」和「剪贴板里是旧
内容」，但两者在「重复选中同一段文字」这一情形下不可分——那恰恰是重选的样子，于是每次重试都被
读成「什么都没复制」。现在以粘贴板的版本号（`changeCount`）变化为落盘证据，落盘且文本非空就是
选区；没有复制动作的应用不会写粘贴板，这条证据本身已经足够。

其二，**观测窗口从 100ms 放到 500ms，并且它是面板显示之后的窗口**。这段窗口由后台收尾线程拥有，
不构成呼出延迟；它决定的是「慢应用有多久把选区放上粘贴板」。只有窗口内落盘的复制才会被采纳并
恢复快照；旧窗口之外落盘的复制既没被采纳、也没人恢复快照——选区被留在用户剪贴板上，这正是
第三条修正要消除的自证陷阱的来源。

其三，**AX 判定三分**（`AxSelection::{Text, Cursor, Opaque}`）。「有文字」「有文本元素但没选中
（光标）」「问不出来」是三件不同的事实，旧代码把后两者合并成一个 `Ok(None)`，再用
`AXSelectedTextRange` 的长度补判，于是「暴露 range、但值为陈旧或恒为零」的应用被直接判为无选区，
兜底根本不运行。现在只有 AX 明确回答「空选区」——并且它自己的 range 不与之矛盾——才跳过兜底；
`Opaque`（没有 AX 焦点、各级都没有 `AXSelectedText`、走查超预算、未授权）一律交给剪贴板裁决。
代价：在「AX 答不出来、range 又确实为零」的应用里，每次呼出会多发一次合成 ⌘C（无选区时它不写
粘贴板，约 20ms 宽限）。这是把「判断依据不可信」换成「一次可忽略的按键」。
