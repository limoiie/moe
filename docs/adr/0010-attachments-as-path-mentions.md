# 附件用 `@path` mention 表达：内容现读，历史只存引用

AI 附件 v1 只收文本与图片（ADR-0005）。需要一个从输入到请求的载体：面板的 ⌘⇧A、侧栏的 📎，以及"附件随消息进入 Conversation"的存储。

## 决策

- **载体是问题文本里的 `@path` mention**，不在 IPC/契约上另开附件参数通道。语法：`@/abs/path`（到空白为止）与 `@"path with spaces"`；`@` 必须落在 token 边界（`foo@bar.com` 不是 mention）。`~` 在写入时展开为绝对路径。
- **输入只管校验与插入**：面板 ⌘⇧A 把 Input Bar 切到路径模式（占位符与提示条变化），Enter 校验后把 `@"path"` 插入原问题；侧栏 📎 在同一位置插入。系统文件选择器留作以后的补充入口。
- **读取发生在请求时**：文本 ≤ 512 KiB 内联进消息（带 `--- 附件 name ---` 分隔），图片 ≤ 5 MiB 转 `data:` URL 进 OpenAI 多模态 `content` 数组；超限/类型不支持在输入处内联报错，历史里的坏引用降级为一行"附件不可读"提示，不失败整次提问。
- **存储只存引用**：`messages.attachments`（JSON 列）存 `{name, path}`；用户可见文本剥离 mention（聊天里以 📎 chip 呈现）。续聊时历史每条消息的附件**重新展开**，所以第二轮问"这个文件"仍带上下文。

## 理由

- 面板与侧栏复用同一 Input Bar 与同一 mention 语义（keyboard-first，一套心智）；平台与 Command 契约不需要新增"附件"通道。
- 只存引用：SQLite 不因 base64 膨胀，也能反映文件的最新内容。

## 代价

- 文件被移动/删除后，历史附件不可读（降级提示，不静默）。
- 请求的可复现性依赖磁盘状态：同一会话在不同时间重放，附件内容可能已变。
