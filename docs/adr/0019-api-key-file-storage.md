# 未签名应用的密钥存储：0600 本地文件代替系统钥匙串

ADR-0005 决定「API key 进系统 keychain」。实机上一个问题随之而来：**每次访问钥匙串都弹授权**
（「moe 想使用钥匙串中的机密信息 / 改进安全性」）。根因是钥匙串的 ACL 绑定应用的代码签名，
而未签名二进制（ADR-0011：不做签名/公证）对系统而言每次都是「未知应用」，点多少遍「始终允许」都不作数。

Raycast 不弹是因为它有 Apple Developer ID 签名；我们目前没有。两条路：

- 开始签名（Apple Developer 账号 + 公证）：恢复钥匙串方案，这是 Raycast 的做法；
- 或把密钥从钥匙串挪出来，用文件存储。

## 决定

**存 0600 本地文件**（`data_dir/moe/api-key`，与 SQLite 同级），同 gh CLI 存 token 的做法：
只有当前用户可读写（0600），不写进配置文件、不回显。读取顺序：文件 →（macOS 一次性迁移）旧钥匙串 →
环境变量 `MOE_AI_API_KEY`。

- 旧钥匙串里的 key 在第一次读取时**落盘迁移**（会触发最后一次钥匙串授权弹窗，之后再也不弹）；
- 面板命令「Moe: 保存 AI Key」与 `key <你的key>` 的文案改为「存本地密钥文件（0600）」；
- `moe-platform/src/keychain.rs` 保留模块名（少 churn），实现换成文件读写，并带 0600 权限的回归测试。

## 代价

- 安全性降一档：钥匙串防的是**同用户的任意进程**读密钥；0600 文件只防**其他用户**。
  本机单用户桌面应用可接受；一旦开始签名，应切回钥匙串（迁移路径反向即可）。
- 用户在钥匙串里留着的旧条目不会再被读写（迁移后落盘），可自行在「钥匙串访问」里删掉。
