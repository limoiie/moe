# 悬浮窗口的阴影交给 AppKit，CSS 只补接触阴影

面板与侧栏都是**透明、无边框**窗口（`transparent: true`），此前还关着系统阴影（`shadow: false`）。
于是「浮起」只能靠 CSS：卡片上是 `shadow-2xl`（25px 偏移、50px 模糊、-12px 收缩）。

问题在于 **CSS 阴影画在 webview 之内，超出窗口边界就被直接裁掉**。卡片四周只留了 12px（面板）/ 8px（侧栏）
透明边距，50px 模糊的阴影在四边被硬切，看起来就是一圈发脏的硬边——正是「阴影看起来怪」的原因。
显式动作胶囊那层 `0 8px 24px / 50%` 的黑影也偏重，在深色卡片上像一块污渍。

Raycast 的做法很朴素：它是一个普通的 macOS 窗口，阴影由系统画，天然可以延伸到窗口矩形之外。

## 决定

1. 两个窗口都打开系统阴影（`tauri.conf.json` 的 `"shadow": true`）。系统阴影基于**窗口内容的 alpha**生成，
   会贴着卡片的圆角形状，并能画到窗口之外——不再有裁切。
2. 每次显示前重算：`moe_platform::mac::refresh_window_shadow(ns_window)`（`setHasShadow(true)` + `invalidateShadow()`）。
   阴影是缓存出来的，透明窗口首次显示时 webview 可能还没画完，不重算就可能拿到「空内容/矩形」的阴影。
   调用点在 `show_panel_blocking` 与 `open_side_view`，两者都已经是主线程。
3. CSS 不再画大阴影：卡片只保留 1px 边框 + `.moe-window-card` 的 1–3px 接触阴影，
   保证在任何桌面背景下都有分界；真正的「浮起」由系统阴影负责。
4. 动作胶囊的阴影收到 `0 1px 2px / 25%` + `0 4px 12px / 22%`：浮在列表之上但不留黑块。

## 代价

- 阴影的观感交给系统（无法自定义颜色、模糊半径、偏移），换 macOS 版本可能略有差异。
- 阴影由内容 alpha 决定：**卡片之外不能出现不透明像素**（例如误加一个不透明背景层），
  否则系统会按整窗矩形算阴影，「圆角卡片 + 矩形阴影」会立刻穿帮。
- 透明窗口的阴影需要内容先画完；新增窗口/新入口时记得在同一处调用 `refresh_window_shadow`。
