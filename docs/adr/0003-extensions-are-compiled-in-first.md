# v1 的 Extension 全部编译内置，但第一天就冻结 Extension/Command/Namespace 语义

做 Raycast 克隆的人默认会假设要先建插件加载器。我们刻意反着来：v1 不引入任何运行时加载机制（WASM/动态库/外部进程都未选型），所有 Extension 编译进主程序；但 Extension（能力聚合 + 独占 Namespace 存储）、Command（可搜索入口 + 数据接口）的概念边界与存储隔离从第一天就按"将来第三方扩展也要遵守"的标准冻结。理由：难逆转的是语义与隔离模型，不是加载器；先让内置功能（AI 问答、回写类命令）验证这套边界，加载器后置选型。
