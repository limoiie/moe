# 结果页只有三种形态，版式与窗口尺寸由平台统一决定

每个命令的结果页都想「自己排一下」，就会长出三套版式：AI 历史搜索一开始是上下分栏，词典类页面将来会再写一遍，
间距、字号、分栏比例各不一样——用户每进一个子应用都要重新适应一次版式，正是 keyboard-first 产品最不该有的税。

Raycast 之所以看起来一致，是因为它的结果视图只有几种固定形态：`List`（可带 `Detail` 侧栏）与 `Detail`（整屏）。
扩展写的是**内容**，不是版式。

## 决定

平台只提供三种页面形态（`ui/src/layout.ts`），扩展只提供内容：

| 形态 | 何时出现 | 版式 | 面板尺寸 |
|---|---|---|---|
| `list` 列表 | 焦点项没有 `detail` | 单列结果，列表吃满宽度 | 768×540 |
| `split` 两栏 | 焦点项有 `detail`（或生成中） | **左侧列表固定 280px 窄栏**（标题 + 时间够用）；右侧详情吃满剩余宽度，顶部是该项的图标/标题/副标题 | 768×540 |
| `detail` 详情 | 结果声明 `detailFull` 且只有一条 | 详情占满，生成中在正文末尾显示行内指示 | 768×540 |

**面板尺寸恒定 768×540**（Raycast 同款：尺寸不随形态变），三种形态只改版式，不改窗口。

- **判定只有一处**：`pageShapeOf(item, detailFull, itemCount)`。UI 的三条渲染路径都从它出发，
  扩展无从「自己排版」——它只能给 `Item.detail` 或声明 `detailFull`（ADR-0013）。
- **尺寸也是全局常量**：`PANEL_WIDTH` / `PANEL_HEIGHT`，经 IPC `resize_panel(width, height)` 下发。
  Rust 侧只做 `set_size` + 按鼠标所在显示器重新居中，策略全在 UI 的形态表里；形态不变就不动窗口。
- **契约镜像也收拢到一处**：`ui/src/types.ts`（命令盘与侧栏共用一份，此前两边各写一遍、已经漂移过）。

给新 Extension 的「怎么用」：照常返回 `Item`，需要右侧详情就给 `item.detail`；要整屏就 `ActionResult::detail(...)`；
其余什么都不用做，版式、分栏、窗口尺寸、键位全部继承。

## 代价

- 只有三种形态：想要「两栏但窗口不变」或「上下分栏」就得加第四种形态——那是产品决定，不是扩展自由。

- 两栏页面的详情栏**不可收起**：它是页面的一部分，`Esc` / 空 `Backspace` 直接回根（命令层），
  不会先关详情栏（此前多一步「收起预览」会让页面退回单列）。只有整屏详情可以收起。
- 列表栏宽（280px）、面板宽高（768×540）是全局常量：要调就改 `ui/src/layout.ts` 一处（好处是全局一致）。
  左侧列表是固定窄栏而不是百分比：详情才是需要宽度的那一半，列表只要放得下标题与时间。
- 窗口尺寸随形态变化会有一次跳变；只在形态切换时发生（不是每次渲染），且面板本来就居中展示。
